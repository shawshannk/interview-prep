C# and .NET

  • Value types copy by value; reference types copy the reference. Where they live (stack/heap) is an implementation detail.
  • record = value equality + with copies; record struct for small value-like data.
  • IEnumerable runs in memory; IQueryable builds an expression tree translated by the provider (SQL).
  • Deferred execution: a LINQ query runs when enumerated — enumerate twice, query twice.
  • async doesn't create threads; awaiting I/O frees the thread until completion.
  • Never .Result/.Wait() in request code (thread-pool starvation, deadlocks in old sync contexts); avoid async void except event handlers.
  • Pass CancellationToken end to end; Task.WhenAll for independent calls, SemaphoreSlim to cap concurrency.
  • GC: Gen 0/1/2 + LOH (≥85,000 bytes); most objects die young; avoid large short-lived allocations, use pooling/ArrayPool/streams.
  • Span<T> is a stack-only ref struct; use Memory<T> across awaits.
  • IDisposable/using for unmanaged resources; IAsyncDisposable for async cleanup.
  • Nullable reference types are compile-time warnings, not runtime guarantees.
  • Exceptions for exceptional cases; Result types for expected business outcomes is a valid team choice.
  • LTS releases (even numbers: .NET 8, 10) get 3 years support; STS (odd) 18 months, extended to 24 VERIFY.

ASP.NET Core and EF Core

  • Middleware order matters: exception handling → HTTPS/HSTS → static files → routing → CORS → authentication → authorization → endpoints.
  • DI lifetimes: singleton (app), scoped (request), transient (each resolve). Never inject scoped into singleton (captive dependency).
  • DbContext is scoped and not thread-safe; in background services create a scope per unit of work.
  • Use IHttpClientFactory (or a static client with PooledConnectionLifetime) to avoid socket exhaustion and stale DNS.
  • Options pattern: IOptions (singleton), IOptionsSnapshot (per request), IOptionsMonitor (change notifications).
  • Filters run inside MVC/endpoint context; middleware wraps everything.
  • Problem Details (RFC 9457) for consistent error responses.
  • EF Core: AsNoTracking for reads; project with Select; Include to avoid N+1; AsSplitQuery for cartesian explosion.
  • SaveChanges is one transaction; use explicit transactions across multiple saves.
  • Optimistic concurrency: rowversion / concurrency token → DbUpdateConcurrencyException.
  • Migrations: review the SQL; expand → migrate data → contract for zero-downtime.
  • Health checks: liveness (process alive, no dependencies) vs readiness (can serve; check critical dependencies).

Node.js, TypeScript and NestJS

  • Node is single-threaded for JS; libuv thread pool (default 4) handles fs, DNS lookup, crypto, zlib.
  • Microtasks (promises, process.nextTick first) run before the next event-loop phase.
  • Block the event loop (sync crypto, big JSON, regex backtracking) → every request stalls. Offload with worker threads.
  • Streams + backpressure (pipeline) for large data; never buffer whole files in memory.
  • Unhandled promise rejections crash the process by default (Node 15+).
  • One process per container; let the orchestrator scale instead of the cluster module.
  • TypeScript: unknown over any; types vanish at runtime — validate input (zod/class-validator).
  • Discriminated unions + never for exhaustive state handling.
  • NestJS order: middleware → guards → interceptors (before) → pipes → handler → interceptors (after) → exception filters.
  • Nest providers are singletons by default; request scope propagates up the dependency chain and costs performance.

SQL and relational databases

  • Clustered index = table order (one per table); nonclustered points to it. Covering index avoids key lookups.
  • Composite index order: equality columns first, then range/sort; leftmost prefix rule.
  • Functions on columns (WHERE lower(email)=…) prevent index seeks unless there's a matching expression index.
  • Isolation: read committed (default) → repeatable read → serializable; SQL Server RCSI/SNAPSHOT and PostgreSQL MVCC avoid reader-writer blocking.
  • NOLOCK = dirty reads, missing or duplicate rows. Not a performance fix.
  • Parameter sniffing: plan compiled for the first value; fixes include OPTION(RECOMPILE), optimize-for, or splitting queries.
  • Deadlocks: access tables in a consistent order, keep transactions short, index foreign keys, retry the victim.
  • Keyset (cursor) pagination over OFFSET for deep pages.
  • PostgreSQL: VACUUM reclaims dead tuples; long transactions block it; JSONB + GIN for semi-structured data.
  • Big-table changes: batch deletes, online index builds, partition for retention.
  • Read replicas lag: route read-your-writes to the primary.

NoSQL, caching and messaging

  • DynamoDB: design from access patterns; partition key spreads load, sort key enables ranges; GSIs are eventually consistent.
  • DynamoDB item max 400 KB; transactions up to 100 items VERIFY; conditional writes for uniqueness/optimistic locking.
  • Hot partitions come from skewed keys, not total capacity; add write sharding or better keys.
  • Redis is single-threaded per shard for commands; avoid KEYS, big keys and long Lua scripts.
  • Cache-aside + TTL is the default; protect against stampedes (locks, early refresh, jitter).
  • Redis Cluster: multi-key operations need the same hash slot ({tag}).
  • Queues are at-least-once: make consumers idempotent; use DLQs; set visibility timeout > processing time.
  • Kafka: ordering only within a partition; key by entity; consumer group parallelism ≤ partitions.
  • Outbox pattern: write the event in the same DB transaction, publish asynchronously.
  • SNS/EventBridge = fan-out; SQS = work queue; Kafka/Kinesis = replayable stream.

HTTP, APIs and the web

  • Safe: GET, HEAD, OPTIONS. Idempotent: plus PUT, DELETE. POST and PATCH are neither by default — use idempotency keys.
  • 401 = not authenticated; 403 = authenticated but not allowed; 409 conflict; 422 validation; 429 rate limited; 503 unavailable.
  • Cache-Control: no-cache = revalidate; no-store = never store; hashed assets get immutable with a long max-age.
  • CORS is a browser policy enforced by the client; it doesn't protect the server from non-browser callers.
  • Cookies for browsers: HttpOnly; Secure; SameSite=Lax (or Strict).
  • TLS 1.3 handshake is 1 round trip; HTTP/2 multiplexes over one TCP connection; HTTP/3 runs over QUIC (UDP).
  • REST for resources and public APIs; gRPC for internal low-latency typed calls; GraphQL for flexible client-driven reads; WebSockets/SSE for push.
  • API versioning: additive changes don't need a version; breaking changes do.
  • React re-renders when state, props or context change; keys preserve identity in lists.
  • Next.js App Router: Server Components by default; add 'use client' for interactivity; mismatched server/client output breaks hydration.

Security

  • AuthN = who you are; AuthZ = what you may do. Check authorisation on every request, at the resource level (prevents IDOR/BOLA).
  • OAuth 2.0 = delegated authorisation (access tokens); OIDC adds identity (ID tokens). SPAs and mobile use Authorization Code + PKCE.
  • JWT validation: signature, issuer, audience, expiry, not-before, algorithm allow-list. Keep access tokens short-lived.
  • Hash passwords with Argon2id, scrypt or bcrypt (salted, slow) — never plain SHA-256.
  • SQL injection → parameterise; XSS → encode output, avoid dangerouslySetInnerHTML, add CSP; CSRF → SameSite + anti-forgery tokens.
  • Secrets live in a secret manager with rotation; never in code, images, logs or front-end bundles.
  • Encrypt in transit (TLS) and at rest (KMS); envelope encryption for app-level crypto.
  • Least privilege for people, services and pipelines; OIDC federation instead of long-lived CI keys.
  • Dependency and container scanning in CI; SBOMs for supply-chain visibility.
  • Log security events, not secrets or personal data.

System design and architecture

  • 1 million requests/day ≈ 12/second; peak ≈ 3× average.
  • 99.9% = 43 minutes down per month; 99.99% = 4.3 minutes.
  • Memory ~100 ns, SSD ~100 µs, same-AZ round trip ~0.5 ms, cross-continent ~150 ms.
  • CAP: during a partition choose consistency or availability; PACELC: otherwise trade latency vs consistency.
  • Quorum: R + W > N for overlapping reads and writes.
  • Scale reads with caches and replicas; scale writes with partitioning, batching and async processing.
  • Every remote call: timeout + bounded retries with exponential backoff and jitter + circuit breaker.
  • Sagas instead of distributed transactions; compensations must be idempotent.
  • Fan-out on write for normal users, on read for celebrities.
  • Modular monolith first; split services when team or scaling boundaries demand it.
  • Strangler fig for migrations; dual-run and compare before cutting over.
  • Choose consistency per feature, and state what you'd monitor.

Cloud and DevOps

  • Shared responsibility: provider secures the cloud; you secure what's in it.
  • Multi-AZ for availability; multi-region for disaster recovery or latency (much harder and more expensive).
  • Private subnets for apps and data; NAT for outbound; VPC endpoints for S3/DynamoDB to cut NAT cost.
  • Security groups are stateful; NACLs are stateless.
  • IAM: default deny, explicit deny wins; roles over users; resource policies for cross-account access.
  • Lambda: 15-minute max, cold starts, concurrency limits; watch DB connections (use RDS Proxy).
  • Fargate for containers without nodes; EKS when you need Kubernetes features and have a platform team.
  • Terraform state: remote, locked, encrypted, access-controlled; review plans in PRs.
  • Build once, deploy many; tag images with the commit SHA.
  • Canary + automated rollback on SLO metrics; feature flags separate deploy from release.
  • K8s probes: liveness restarts, readiness gates traffic; set requests/limits; memory over limit = OOMKilled.
  • Cost: tag everything, set budgets, rightsize, Savings Plans for baseline, Spot for batch, watch egress and log volume.

Observability, testing and reliability

  • Logs (events), metrics (aggregates), traces (request paths); correlate with a trace ID.
  • OpenTelemetry: API + SDK + collector; vendor-neutral.
  • RED for services (rate, errors, duration); USE for resources (utilisation, saturation, errors).
  • SLI → SLO → error budget; alert on burn rate, not individual errors.
  • Watch p95/p99, not averages.
  • Test pyramid: many unit, some integration (Testcontainers), few end-to-end; contract tests between services.
  • Coverage measures executed lines, not correctness; mutation testing checks test strength.
  • Incidents: mitigate first (rollback, flag off), then find root cause; blameless postmortems with owned actions.

GenAI

  • 1 token ≈ 4 characters of English; you pay per input and output token; output costs more.
  • Low temperature for extraction/classification; temperature 0 isn't perfectly deterministic.
  • Facts → RAG; behaviour/format → prompting then fine-tuning; actions → tool calling.
  • RAG: chunk → embed → index; query → hybrid retrieve with ACL filters → rerank → grounded prompt with citations.
  • Same embedding model for indexing and queries; changing it means re-embedding.
  • Evaluate retrieval (recall@k) separately from generation (faithfulness, relevance).
  • Build a golden dataset early; run evals on every prompt/model change.
  • Prompt injection can come through retrieved documents; the system prompt is not a security boundary.
  • Tools: validate arguments in code, least privilege, human approval for irreversible actions.
  • Cut cost: smaller models for easy tasks, fewer chunks, prompt caching, response caching, max-token caps, batch APIs.
  • Stream responses for perceived latency; parallelise retrieval and lookups.

DSA patterns

  • Hash map/set: O(1) average lookups — pairs, counts, seen-before.
  • Two pointers: sorted arrays, palindromes, pair sums. Sliding window: longest/shortest subarray with a condition.
  • Binary search: sorted data or monotonic answer space ("minimum capacity that works").
  • BFS for shortest path in unweighted graphs; DFS for connectivity, cycles, backtracking.
  • Heap (PriorityQueue<TElement,TPriority>): top-k, merge k sorted, scheduling.
  • Topological sort for dependencies; Dijkstra for non-negative weighted shortest paths.
  • Dynamic programming: define the state, the transition, the base case; memoise then tabulate.
  • Prefix sums for range sums; monotonic stack for next greater element.
  • Say the brute force first, then optimise; state time and space complexity.
  • Constraints hint the target: n ≤ 10^5 → O(n log n) or better; n ≤ 20 → exponential is fine.

Leadership and behavioural

  • STAR: Situation and Task short (20%), Action detailed with "I" (60%), Result with numbers and learning (20%).
  • Have 8–10 stories ready that each cover several themes (conflict, failure, influence, delivery, mentoring, ambiguity).
  • Disagree with data, propose alternatives, then commit once decided.
  • Underperformance: clear expectations, specific feedback, support plan, documented follow-up.
  • Estimates: ranges with assumptions; re-plan early when scope or risk changes.
  • Technical debt: tie it to business impact (incidents, lead time), budget it continuously.
  • Hiring: structured interviews with rubrics; calibrate interviewers.
  • Delegation: match task to growth goals; agree on outcome and check-ins, not method.
  • Stakeholders: no surprises — communicate risks early with options.
